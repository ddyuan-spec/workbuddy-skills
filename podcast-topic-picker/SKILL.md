# 播客选题助手（podcast-topic-picker）

当用户说"想个播客选题 / 帮我选题 / 下期聊啥"时，按本流程执行。目标：产出可立即排期的选题，且每个选题都配有能征集故事、确认角度的问卷，并把素材沉淀进可维护的知识库。

## 适用前提
- 喜剧 / 杂谈 / 闲聊类播客为主，但流程通用。
- 需要腾讯文档 MCP（mcp__tencent-docs）已连接，用于产出在线文档。
- 用户本地可能有《播客问题库.docx》（普鲁斯特问卷母本）和《播客BGM背景音乐库.xlsx》，优先读取复用。

## 执行流程

### 1. 读取已有素材（如有）
- 用 python-docx / openpyxl（在隔离 venv 中）读取桌面上的问题库与 BGM 库，提取问卷母本与 BGM 标签，供知识库与选题映射复用。
- 若文件不存在，跳过并在知识库里标注"待补"。

### 2. 检索网上最火话题
- WebSearch 同时覆盖：①中文喜剧/杂谈播客排行与趋势；②海外热门 podcast（comedy/talk）；③当前时令/季节相关选题（如暑期、开学季、节日）。
- 提炼"共性规律"（如：喜剧人控场 + 无脚本 + 接地气 + 奇人异事）和"已验证有共鸣的时令选题"，作为选题参考。

### 3. 反问澄清（关键，不可跳过）
用 AskUserQuestion 反问 3-4 个决策性问题，例如：
- 主播形式/人设：好友闲聊2-3人 / 单口喜剧式个人 / 嘉宾对谈 / 听众连麦
- 时令节点：当下季节、开学季、节日，或"综合推荐"
- 目标听众：学生/年轻群体 / 通勤打工人 / 广撒网 / 特定圈层
- 产出数量：3 试水 / 5 精挑 / 8-10 排期
若用户已指定某个选题（如"大一总结会"），尊重并纳入，同时补问其余未知项。

### 4. 生成选题列表 + 选题模板
为每个选题给出：钩子、时令/节点、目标听众、形式、爆款参考、可讲角度（候选3个）、故事缺口、BGM建议、状态。
附两份可复用模板：
- **选题模板表**（字段：选题名/钩子/时令/听众/形式/爆款参考/角度候选/故事缺口/问卷/BGM/状态）
- **选题打分卡**（时令契合度/共鸣强度/出梗潜力/故事可得性/嘉宾可达性/差异度，每项1-5，≥20分才做）

### 5. 为每个选题生成配套问卷
每份问卷含三段：
- A. 故事征集（标 ⭐ 必填，收集真实素材以确认可讲）
- B. 角度确认（帮主播判断从哪个角度讲最出彩）
- C. 物料/嘉宾准备（内部）
可选引用普鲁斯特问卷作为嘉宾开场母本。

### 6. 搭建知识库（文件夹）
知识库文档含：①人设卡/节目定位 ②BGM映射版（按情绪/场景标签重排）③普鲁斯特问卷（28题）④爆款趋势参考 ⑤使用索引。

### 7. 推成腾讯文档（在线）
> 重要：腾讯文档 MCP 的坑，必须照做，否则静默失败。
- 工具名用**点号**：`mcp__tencent-docs__create_space`、`mcp__tencent-docs__manage.create_file`、`mcp__tencent-docs__doc.insert_markdown`（不要用下划线）。
- `create_space` 拿到 `space_id`；再用 `manage.create_file`（file_type=doc，带 space_id）在空间内建空文档，得到 `file_id`。
- **灌内容用 `doc.insert_markdown`，`idx` 必须 ≥ 1**（传 `idx:0` 会被当成 falsy 丢弃，报"missing required parameters: [idx]"）。空文档用 `idx:1`。
- **不要传空字符串参数**（如把占位文本替换为 `""` 也会被丢弃）。需要清空时传一个空格 `" "`。
- `insert_markdown` 支持明文 `markdown` 参数（与 `base64_markdown` 二选一）；内容含大量特殊字符时优先用 base64 更稳。
- 建议建一个空间作为"选题文件夹"，里面放：选题列表、各选题问卷、知识库。

### 8. 交付
- 返回空间/文档链接，并简述 3 个选题与下一步（主播填问卷→确认主角度→排期）。
- 本地也保留一份 Markdown 备份。

## 注意事项
- 用户偏好"自然、去 AI 味"的表达；选题名和钩子要口语化、有梗，别端着。
- 喜剧杂谈重在"真实+松弛"，宁可选题小、故事真，不要大词空谈。
- 若用户后续要加选题，复用同一空间，沿用选题模板与打分卡，保持知识库随更随维护。
