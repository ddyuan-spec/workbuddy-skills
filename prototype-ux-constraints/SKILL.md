# 原型UX约束规范（前端交互）

## 触发条件

- 生成/修改任何含前端交互的原型（H5 / App / 小程序 / 后台管理端）时必须调用。
- 特别适用场景：商品购买级别限制、权限拦截、会员等级限制、资格校验等前端反馈。

## 核心约束

### 1. 禁止多余说明文案

- ❌ 禁止在原型页面内写「前端拦截说明」「规则说明」「* 注意」「演示：当前...」等解释性卡片或段落。
- ❌ 禁止在规格/选项/字段下方写「后台设置了 xxx」「该字段含义是 xxx」「仅辅助提示」等备注。
- ❌ 禁止在页面角落、右侧、底部加演示说明、状态注释、图例。
- ✅ 所有业务规则、异常说明、字段映射应放入 PRD；原型只保留真实界面元素。

### 2. 禁止前端小字限制标签（重要）

- ❌ 禁止在规格按钮、选项标签、商品名称、价格旁加 tiny 小字限制提示，例如：
  - `🔒限高级`、`限高级+`、`限VIP`、`仅限会员`、`会员专享`、`仅对高级会员可见` 等。
  - 任何 `font-size ≤ 10px` 且含「限」「仅限」「专享」「会员可见」「🔒」等字样的标签/角标。
- ✅ 购买级别限制只通过**后台配置字段**（如「购买级别(≥)」下拉）和**加购/购买时的全局 Toast** 表达，不在前端界面上贴小字提示。
- ✅ 若需要让用户感知级别门槛，通过 PRD 描述，不在原型里加视觉标签。

### 3. 小字限制文案扫描与确认 Loop（强制）

生成/修改原型后，必须执行以下扫描 loop，直到无命中项：

1. **正则扫描**：在 HTML/CSS/JS 中搜索以下模式：
   - 文本内容含 `限`、`仅限`、`专享`、`会员可见`、`🔒` 等关键字。
   - 类名如 `.lock`、`.limit`、`.vip-tag`、`.member-only` 等。
   - `font-size:9px`、`font-size:10px` 等 tiny 样式附近有限制含义文案。
2. **用户确认**：每发现一处，向用户展示具体代码片段，询问「这段小字限制标签是否需要保留？」
   - 用户回答**不要** → 立即删除，并记录该文案模式到记忆。
   - 用户回答**保留** → 保留，并记录为例外。
3. **记忆生效**：用户已确认删除的小字模式，**后续同类型无需再问，直接删除**。
   - 记忆写入位置：`C:\Users\13364\WorkBuddy\绿韵家\.workbuddy\memory\MEMORY.md` 与 `~/.workbuddy/MEMORY.md`（跨项目）。
   - 记忆格式示例：「前端原型中规格/选项旁的“🔒限高级”“限高级+”“限VIP”等 tiny 限制小字，用户已确认不需要，后续直接删除。」
4. **重新扫描**：删除后继续 loop，直到扫描无命中。

### 4. 禁止臆测新样式/组件

- ❌ 禁止为了一次提示单独设计气泡 `.bubble` `.fe-bubble` `.tip` `.hint-pop`、小红标说明、新模态弹窗样式。
- ✅ 复用项目现有全局组件：全局 Toast / 全局弹窗 / 页面已有提示样式。
- ✅ 提示文案极简，只保留必要一句，例如「该商品仅限高级会员及以上才能购买」。

### 5. 拦截提示时机（购买级别 / 权限类场景）

- ❌ 用户**选中规格 / 切换选项 / 点击单选**时**不触发**任何拦截提示。
- ✅ 只有用户点击**加入购物车**、**立即购买**或实际提交动作时才触发提示。
- ✅ 提示后保持规格可选中状态，**不做置灰、不阻断继续切换规格**。

### 6. 交互即交互，不堆说明

- 原型里每个可点击元素必须有对应反馈。
- 不要为了让评审者看懂而加文字说明；看不懂的走 PRD 和面对面沟通。

### 7. 先盘点既有原型，能复用就复用（禁止从零重造）

- ✅ 画新需求原型前，**先盘点项目内既有同模块原型**（如 `优惠券体系/*.html`、其他需求文件夹的 `*.html`），列出可复用的页面 / 组件 / 样式变量。
- ✅ 能复用的页面直接**复制改造**（改成本期范围、删掉不做的分支），复用既有类名、Toast / 弹窗实现，保持跨原型视觉一致。
- ❌ 禁止对已经存在的交互页面从零重写；只在既有原型缺页时新建。

### 8. 后台 / 管理端原型必须基于参考样式页

- ✅ 画后台 / 管理端（平台端后台、商家端后台）原型前，**必须先定位样式参考页**（项目内优先 `优惠券体系/live-admin.html` 等既有后台原型）。
- ❌ 禁止凭空臆测后台布局 / 表格 / 表单 / 弹窗样式。
- ⚠️ **若全盘找不到任何参考页，必须主动找用户要样式参考**（用 AskUserQuestion 或文字提问），拿到前不产出后台原型。此动作已固化为强制前置步骤。

### 9. 逐页 / 逐弹窗样式参考确认（强制 Loop）

画后台原型时，**不能只找一个全局参考页就全盘套用**。必须按以下流程逐一确认：

1. **列出全部页面 + 弹窗/抽屉清单**：先列出原型包含的所有页面（侧栏页）和所有弹窗/抽屉/详情页，编号命名。
2. **逐个 AskUserQuestion 确认样式来源**：对每一项问用户：
   - 「你有这个页面的样式参考截图/设计稿吗？」
   - 选项：`有参考，我给` / `沿用已有参考的同套风格` / `暂无，先画通用风格`
3. **记录样式参考矩阵**：汇总成表（名称 × 样式来源决策），存入记忆。
4. **缺参考的不画**：用户说「有参考，我给」但还没给的项，**等收到截图后再画该项**；其他项可先行。
5. **样式一致性**：多项选「沿用同套风格」的，共享同一套 CSS 变量与组件类名。
6. **修正即循环**：若用户在审查中发现某项实际样式与参考不符（如「不是抽屉是详情页」「不是弹窗是内嵌表单」「不是弹窗是独立编辑页」），立即修正并重新 loop 自检。

### 10. 后台（平台端/商家端）增/改/查一律跳转独立页，禁用 Modal 弹窗

- ✅ 后台管理端（平台端后台、商家端后台）的所有「新增」「编辑」「详情」操作，**一律跳转独立页面（独立 view / 路由页）**，**不使用 Modal 弹窗**（`.modal-overlay` / `.modal`）。
- ❌ 禁止用 `openXxx()` + `modal-overlay.classList.add('show')` 这种弹窗模式实现后台新增/编辑/详情。
- ✅ 独立页结构：`phead`（返回按钮 + 动态标题 h2）+ `form-section`（表单主体）+ `form-actions`（取消/返回 + 保存/提交）。
- ✅ 列表页「新建」按钮 `onclick="go('xxxNew')"`；列表「编辑」链接 `onclick="editXxx(id)"` → `go('xxxEdit')` 后 `fillXxx(id)` 回填；保存后 `go('list')` 回列表；`go()` 的 view map 必须登记这些独立页。
- ✅ 详情页也是独立 view（如 `viewCouponDetail`），含「返回列表」+ 业务操作按钮（如「下架」）。
- ✅ 编辑回填：进入编辑页时从数据重建表单（含从选项池移动已选项时，**离开/重置表单须恢复选项池**，避免多次编辑后选项池被掏空的交互 bug）。
- ⚠️ 此规则优先级高于「复用既有弹窗式后台原型」：若既有后台原型用 modal 实现增改，**改造时改为独立页**。
- ⚠️ 用户在审查中说「这个弹窗应是独立编辑页/详情页」时，立即按此规则重构（实例：某项目曾把券详情从抽屉改为独立页、把新增券/发券活动/领券活动的 modal 弹窗全部改为跳转独立页）。

## 11. 自动化冒烟测试（强制，替代纯人工 Loop —— 交付前必跑）

人工肉眼 Loop 不可靠：曾两次漏掉"独立页写在 `</main>` 之外 → 点击跳转后整页空白"的致命 bug（用户侧表现为"发券/领券的编辑和新增是空白页"，loop 的"交互完整性/样式正确性"逐条勾选却全过）。**改为用 jsdom 真实执行原型 JS 的自动化冒烟测试作为硬性门禁**：

- 检查器：`references/proto_smoke.js`（已随本 skill 提供，单文件零依赖，需 jsdom；缺失时自动临时安装）。
- 运行（在原型所在目录）：
  ```
  NODE_PATH="<jsdom 所在 node_modules>" <managed-node> references/proto_smoke.js <原型.html>
  ```
  例：
  ```
  NODE_PATH="C:\Users\13364\.workbuddy\binaries\node\workspace/node_modules" "C:\Users\13364\.workbuddy\binaries\node\versions\22.22.2\node.exe" references/proto_smoke.js 平台端后台原型.html
  ```
- 检查项（任一项失败 → 禁止交付，先修复）：
  1. **[A] 视图容器归属 `<main>`**：所有 `view*` 独立页 / 弹窗必须在 `<main>` 内，写在 `</main>` 之外直接判失败（空白页根因）。
  2. **[B] `go()` 可达性 + 空白校验**：每个 `go('X')` 目标视图必须存在、跳转后可见、且有内容（非空白页）。
  3. **[C] 真实点击每个可交互元素**：捕获 JS 运行期错误（如 `undefined.trim()`、未定义变量）。
  4. **[D] onclick 函数未定义扫描**：所有 `onclick` 引用的函数必须已定义。
  5. **[E] JS 运行期错误汇总**：`virtualConsole` 捕获的所有 jsdomError / console.error（已对 `confirm/toast/$` 等浏览器环境项注入 shim，仅报真实 bug）。
- 退出码：0=全部通过可交付；1=有失败项；2=参数错误。**任何失败项都必须修复后才能交付原型。**
- ⚠️ 本测试已用正/反例验证：健康文件全绿；把发券/领券独立页移到 `</main>` 外会立即报 `#viewSendEdit/#viewClaimEdit 写在 </main> 之外 → 跳转后空白页`。

## 交付前自检 Loop（生成 / 修改原型后必须 loop 执行，直到全部通过）

> ⚠️ **本 Loop 必须与 §11 自动化冒烟测试共同执行**：先跑 `proto_smoke.js` 且零失败、零 JS 错误，再做下列人工逐项核对。自动化测试不通过一律禁止交付。人工 Loop 负责自动化测不到的视觉/文案层面（样式错乱、冗余文字、小字限制标签、复用一致性），自动化测试负责 DOM 结构 / 交互可达性 / JS 错误层面。

每轮检查后修正问题并重新检查；以下任一项不通过则继续 loop，禁止带着问题交付：

- [ ] **交互完整性**：页面内每一个按钮 / 链接 / 标签切换 / 表单提交 / 状态变更都有对应反馈（点击、跳转、弹窗、Toast、显隐切换），无「死」交互、无掉落的交互分支、无只画不响应的元素。
- [ ] **样式正确性**：无布局错乱、无未定义 / 裸样式类、无溢出 / 重叠 / 文字截断、无响应式破版、无错别字 / 残缺文案。
- [ ] **无冗余说明文字**：页面内无「说明」「规则」「注意」「演示」「备注」「图例」「前端拦截」类文字块（业务规则只在 PRD）。
- [ ] **无小字限制标签**：页面内无 `🔒限高级`、`限高级+`、`限VIP`、`仅限会员` 等 tiny 限制小字；已按 §3 扫描并处理。
- [ ] 无新增气泡 / 弹窗样式类（搜索 `.bubble` `.fe-bubble` `.tip` `.notice` 等）。
- [ ] 选中规格 / 选项的函数内无提示调用（`toast` / `alert` / `showBubble` 等）。
- [ ] 仅「加入购物车」「立即购买」或提交动作函数内有提示调用。
- [ ] 提示使用现有全局 Toast / 弹窗，而非新建 DOM 组件。
- [ ] **后台增改查无 Modal**：后台平台端/商家端的所有新增/编辑/详情均为独立页（grep `modal-overlay` 应零命中），无弹窗式增改。
- [ ] **DOM 结构校验（视图容器归属）**：所有 `viewXxx` 独立页 / 弹窗必须在布局容器（`<main>` / 内容区）**内部**，禁止写在 `</main>` 或内容区闭合标签之外（否则跳转后显示空白页）。检查方法：确认 `</main>` 或等效内容闭合标签的位置，所有视图 div 必须在其之前。⚠️ **真实案例**：某次把 3 个独立页写在 `</main>` 之后，导致点击"新增"跳转后完全空白 —— loop 的"交互完整性"和"样式正确性"均未捕获此 bug，必须专项检查。
- [ ] **复用核对**：后台原型已基于参考页（或已找用户要到参考）；前端原型已复用既有同模块原型的可复用部分，无重复造轮子。

## 与 requirement-workflow 的关系

本 skill 是 `requirement-workflow` Step 3「输出可交互原型」的前端交互子约束。在生成前端原型前，先调用本 skill（含 §7 盘点复用、§8 后台参考页、§3 小字扫描、交付前 Loop 自检），按上述约束调整后再进入产出校验 Hook。
