# 本轮改动执行报告（exec-report）

## 用途
一轮 PRD / 原型 / skill 改动收尾时，生成一份**给人或给领导看**的简洁执行报告。不重复 PRD 内容，只讲"改了什么、验证过什么、线上在哪、还差什么"。

## 触发时机
- 用户说"出个执行报告""这轮改了啥""汇报一下""改动汇总"。
- 或一轮多文件改动（PRD + skill + 原型）完成后自律生成，便于用户直接转发。

## 报告结构（固定四段）

### 1. 改动清单
表格：`| 文件/对象 | 类型 | 具体改动 |`
- 类型：PRD 章节 / skill 规则 / 原型页面 / 推送
- 例：`优惠券体系新需求PRD.html` / PRD / 补 §10.7§10.8、§4.1.6 补计算公式与数据演练、§4.3 重编号、版本号 V1.0.31→V2.0

### 2. 验证结果
- 结构排查：prd-structure-checker 通过 / ⚠️单薄（列缺项）
- 自动化：proto_smoke.js / proto_smoke_client.js 零失败零 JS 错误（原型类）
- 推送验证：raw.githubusercontent grep 命中新内容（True/False）
- skill 纪律：空槽跳号豁免 / 二期待办禁写记忆 等已固化

### 3. 推送状态（线上短链）
- 列出已推送的线上链接（如 `https://ddyuan-spec.github.io/taixiaohu/coupon-prd.html`）
- 标注哪些**未推送**（待用户确认）

### 4. 待办 / 待确认
- 二期待办（**仅列在 PRD §十一，不写项目记忆**）
- 用户待确认项（⚠️ 待确认 @干系人）
- 下一步建议（按优先级）

## 红线
- ❌ 把 PRD 全文/原型代码塞进报告——报告是"索引+结论"，细节去 PRD/原型看。
- ❌ 把二期待办写进项目记忆（MEMORY.md / 每日流水）——按 prd-structure-checker §4.35，二期待办仅维护在 PRD §十一。
- ✅ 给用户的是**可直接转发的短报告**，突出业务价值与 action。
