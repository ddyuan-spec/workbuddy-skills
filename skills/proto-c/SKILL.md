# 原型C端-交互（proto-c）

C 端**带交互**前端原型 skill。泰小虎项目强制先查知识库页面图再画。

## 触发（用户说这些即加载本 skill）
画原型 / 改原型 / 前端原型 / C端原型 / App原型 / 小程序原型 / H5原型 / 手机端原型 / 带交互原型 / 可点击原型 / 高保真原型

## 范围
生成/修改任何 C 端**可交互**前端原型（App / 小程序 / H5 / 手机网页，含点击跳转、状态切换、弹窗、Toast、表单）时强制加载。

## 与「设计原型(平铺)」的边界（勿混）
| 产出 | 走哪个 skill | 关键差异 |
|---|---|---|
| 带交互、可点击、有跳转/状态/弹窗 | **本 skill（proto-c）** | 跑冒烟、三态拆独立页、JS 交互 |
| 无交互、可复制源码、供墨刀/评审的平铺图 | **proto-design（设计原型）** | 不跑冒烟、走 flat_delivery_checklist、标注「无交互」 |

用户只要平铺图/墨刀稿/可复制源码 → 直接路由到 proto-design，不要在本 skill 画完再「假装平铺」。

## 强制门禁（自管，不依赖其他 skill）
0. **PROTO-INT-001 需求九步确认**（BLOCKER）：拿到需求先逐条对照九步清单（视觉标准/流程图/页面清单/状态规则/交互规则/特殊任务/示例数据/禁止项/验收标准），任一缺失必须 `AskUserQuestion` 让用户补全，齐全后才进后续门禁——禁止用户只给一句「做个XX原型」就直接开画。
1. **REQ-FLOW-022 知识库 UI 索引先行**（BLOCKER，项目级 taixiaohu）：画前先 Read `泰小虎UI_catalog.md` → `route_pages.py` 路由命中 1~3 张参考页；未命中必须 `AskUserQuestion` 反问「要参考哪页」，禁止按记忆/demo 蓝紫画。无 catalog 项目跳过此条。
2. **PROTO-STY-002 首步定位设计规范**：动手前 locate 并 Read 项目 C 端设计资产（spec.md / constitution.md / 真实截图 / 既有同模块原型），确认基线。
3. **PROTO-STY-003 真实截图 1:1 套用**：用户给了真机截图，逐字套用色值/描边/Tab 高亮，禁通用风格化。
4. **PROTO-STR-003 三态列表拆独立页**：状态≥3 必须拆独立移动端页，禁单页 Tab 切。
5. **PROTO-SMK 交互冒烟**：交付前必跑 `references/proto_smoke_client.js`，退出码 0 才许交付。脚本已含 **[A]–[H] 八段扫描**（页面归属 / go 可达 / 点击零错 / onclick 已定义 / JS 错误 / 表单去重 / [G] 逻辑反模式 / [H] 引用完整性·dead-reference），[H] 为防「脚本过期漏检」与「删定义留调用/样式」的机器门禁（见门禁 #8）。
6. **PROTO-SMK-005 交互逻辑审计**（BLOCKER）：冒烟通过 ≠ 可交付。交付前必须跑冒烟脚本的 **[G] 交互逻辑反模式扫描**（自动卡住「累加函数定义了却从不调用 / 完成或跳转用 Math.random 决定 / 完成处理器只翻显示不碰真实任务数据」三类硬伤），并**人工逐项核对 checklist 的 C24（状态机一致性）/ C25（数值累加真实生效）/ C26（无随机跳转与垃圾数据）**，任一项不通过禁止交付。
7. **PROTO-SMK-006 真实点击穿透（BLOCKER，最后一道关）**：交付前必须跑 `references/proto_clickthrough_client.js`，用 jsdom 模拟真人**逐个点击每个交互入口并断言状态真的变了**（虎力值有无 +N、任务卡有无打勾、页面有无切换、弹窗有无出现、入口卡片/顶部 Tab 有无死交互）。退出码非 0（出现死交互或状态不联动）**禁止交付**。这是冒烟（只查「点一下不报错」）和 [G] 扫描（只查「写法反模式」）都查不出的「交互结果正确性」兜底——**绝不允许只跑了冒烟/[G] 就宣布交付**。**新增任何交互入口（新页面/新按钮/新 Tab）必须同步在本测试补对应 Step 的点击+断言**，否则 [H1] 会报「该页面未被点击穿透脚本覆盖」强制你补 Step。
8. **PROTO-SMK-007 引用完整性 / dead-reference 扫描（BLOCKER，嵌入冒烟 [H] 段）**：覆盖本次（睡眠任务闭环 v7）迭代实测踩中的三类回归——**R1** 点击穿透脚本断言的是历史旧 id，与原型对不上 → 测试假通过、漏检真交互；**R2** 删了函数定义却残留调用（如 `renderHuli()`）→ 运行期 ReferenceError，主流程弹窗弹不出；**R3** 删了 CSS 类定义却残留 `class` 引用（如 `.huli-btn`）→ 按钮样式崩。机器门禁：**[H1]** 点击穿透脚本（`proto_clickthrough_client.js`，与冒烟同目录，自动定位）引用的每个 `#id` 必须在原型中存在（否则该 Step 会 null 崩溃，正是 R1），并反向报出未被脚本覆盖的 `.page`（强制补 Step）；**[H2]** 原型 `<script>` 调用的每个裸函数必须已定义（否则 ReferenceError，R2）；**[H3]** 原型使用的组件类必须在 `<style>` 有规则（WARN，R3）。**[H1][H2] 不通过禁止交付**；扫描前已剥离 `//` 与 `/* */` 注释，避免注释文本误判。

## 标准流程
0. **需求九步确认**：解析需求，对照九步清单（视觉标准/流程图/页面清单/状态规则/交互规则/特殊任务/示例数据/禁止项/验收标准）自查齐备度；缺失步用 AskUserQuestion 一次性补全（选项含「我马上补 / 沿用上一版 / 自由发挥」），齐全才继续。
1. **知识库先行**：Read catalog → `route_pages.py "<关键词>"` → 只 Read 命中页；未命中反问。
   > 定位：`泰小虎UI_catalog.md` 与 `route_pages.py` 在**项目工作区根目录**（如 `C:/Users/13364/WorkBuddy/任务目标流程化/`），不在本 skill 目录。找不到时先 Glob `**/泰小虎UI_catalog.md` 定位；确实没有则跳过本分支。
2. **读基线**：PROJECT 设计规范 + 真实截图（有则 1:1 套用）。
3. **画交互原型**：单 `.phone` 外壳 + 多 `.page`（go() 切 `.active`）+ 全局 Toast；所有 view 写在 `.phone` 内（PROTO-STR-002）。
4. **跑冒烟**：`NODE_PATH="<node_path>" <node> references/proto_smoke_client.js <原型.html>`，退出码非 0 禁止交付。
5. **交互逻辑审计 + 人工 checklist**（**务必真正逐项执行并报告每项证据，禁止只跑冒烟就宣布交付**）：
   - 先跑冒烟脚本的 **[G] 交互逻辑反模式扫描**，G1（累加函数定义了却从不调用）/ G2（完成或跳转用 Math.random 决定）必须为 0 失败；G3（完成处理器只翻显示不碰真实任务数据）警告必须人工核对确认非假完成。
   - 再逐项核对 rules.json `checklist` 全部条目（当前 **C01–C28**），重点执行 **C24 状态机一致性 / C25 数值累加真实生效 / C26 无随机跳转与垃圾数据 / C27 真实点击穿透 / C28 主流程贯穿** 五项交互逻辑审计——含状态机的原型必须实际走一遍主流程断言结果（领→列表填充、完成→数值 +N、页面状态联动），而非只验证「点一下不报错」。
   - 最后跑红线扫描（PROTO-TXT-007 Loop）。
   任一项不通过禁止交付（PROTO-SMK-003：冒烟通过 ≠ 可交付；PROTO-SMK-005/006：交互结果正确性强制门禁）。
6. **真实点击穿透（PROTO-SMK-006，强制）**：`NODE_PATH="<node_modules>" <node> references/proto_clickthrough_client.js <原型.html>`，退出码非 0 禁止交付。**本测试脚本必须随原型迭代同步更新**（新增交互入口要在脚本补 Step），否则该入口视为未验证。
7. **交付**：过 delivery-suite 推送 GitHub Pages / 转 Word；PRD 引用其截图时过 prd-suite。

## 红线速记（详见 rules.json）
- 禁冗余说明文字 / tiny 限制标签 / 选项态 hint 小字 / NEW 角标（PROTO-TXT 系列）
- 禁新建气泡/弹窗样式组件，复用全局 Toast（PROTO-STY-006）
- 提示只在实际提交动作触发，不在切换选项时（PROTO-STR-005）
- 复用既有同模块原型，禁静默删字段（PROTO-STR-006/007）
- 需求九步未确认齐全不动手，缺的先问用户补（PROTO-INT-001）
- 原型视觉验收截图用真实浏览器引擎（playwright chromium）截，勿用 Edge headless——后者时机不可靠会漏掉「样式崩」类视觉问题（v7 复盘 R5）
