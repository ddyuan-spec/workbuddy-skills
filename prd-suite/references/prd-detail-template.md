## 二、单页标准结构（docx 示例权威结构，本期新增/改动必须齐备）

> 以下 6 个子节是 docx「三、功能需求详情」+「示例」定义的**每页必备项**。
> 缺失任意一项，`--strict` 模式判 🔴 阻断。

### 2.1 页面原型与交互示意
- **必须贴原型截图**（交互式 HTML 仿真原型截图 / 墨刀导出图），用 `<img>` 标签内嵌，**禁止用流程 SVG 充当界面截图**。
- 截图须与本节页面一一对应（一个视图一张图，列表/表单/弹窗/详情分开）。
- 交互说明（点击、滑动、弹窗、遮罩等手势与动态反馈）在此或 2.2 中描述。

### 2.2 详细逻辑规则
分两层展开：

**界面与展示规则**
- **入参校验**：仅当满足什么条件才在此曝光 / 可操作（如后台配置「发放中」且适用当前商品才展示）。
- **极限值处理**：文字最多显示字数、超出打点规则、空状态/缺省图与文案、输入框最大字符、价格金额展示极限。

**业务逻辑与边界条件**（凡涉及状态/资产变更必须写）
- **未登录拦截**：游客态点击核心按钮的处理（直接拉起登录 / 先引导；登录后是否自动续作）。
- **交互反馈**：操作成功/失败的前端反馈（toast / 弹窗 / 状态变更）。
- **按钮状态切换逻辑**：由后端接口实时判断的按钮态（未领取/已领取/已抢光/置灰规则）。
- **防刷控制**：前端防重抖、loading 态、并发防重复提交。

### 2.3 列表字段表（列表类页面必备）
表头：**字段名称 / 需求说明 / 备注**
- 需求说明写明：按导入 / 前端输入 / 后端返回；是否支持编辑。
- 附加规则必须单列：**排序**（按 XX 倒序）、**分页**（20/50/100 切换，默认 20）、**合计行**（范围为全部结果）、**数据唯一判断**（字段组合唯一）。

### 2.4 功能按钮总表 + 每个按钮独立小节（有操作按钮的页面必备）
- 总表表头：**功能名称 / 功能说明 / 备注**。
- 每个按钮再开独立小节，强制四要素 + 逐步逻辑：
  1. **功能说明**：一句话。
  2. **显示位置**：列表操作列 / 主按钮 / 更多下拉。
  3. **权限**：菜单查看权限 + 按钮权限（角色 / 数据范围）。
  4. **前置条件**：状态约束（如「未确认支持删除」）。
  5. **功能实现**：**逐步操作逻辑 + 异常分支 + 校验提示文案**（如未勾选→「请选择数据」；勾选已确认→「仅未确认支持确认」）。

### 2.5 编辑 / 新增表单（表单类页面必备）
表头：**区域 / 字段 / 功能逻辑说明 / 备注**
- 每个字段写清：默认显示 or 隐藏、可编辑 or 不可编辑。
- 输入限制：必填 / 非必填 + 类型（数字/文本/下拉单选）+ 长度 + 小数位 + 正整数/大于 0 等。
- 下拉选项取值来源（如「取系统管理→基础资料→组织机构」）。
- **计算公式单独列出**（如小计 = 重量 × 单价），附数据演练保证合计守恒。

### 2.6 查询条件（列表类页面必备）
表头：**查询条件 / 查询说明**（控件类型 + 选项来源 + 查询行为）。
【搜索】统一提交；【清空】恢复初始不提交。

### 2.7 数据来源（字段级，凡有字段必写）
表头：**字段名称 / 取值逻辑说明**
- 「取《XX 表》相同字段」「调用 XX 接口成功后存储」「前端本地 / 后端 / 第三方」。
- 主表 / 子表分别说明来源。

## 三、状态流转（凡涉及状态变化的实体必备）
提供**状态流转表**：起始状态 + 触发动作(Action) + 前置/后置条件 = 目标状态。
每个破坏性操作（删除/作废/下架）须限定合法起始状态 + 业务级前置条件（非仅确认弹窗）。
