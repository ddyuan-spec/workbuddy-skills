# safe-edit-delete（删除/编辑安全纪律）

**适用**：任何"删 / 移除 / 清理 / 改"类指令，特别是原型 HTML、PRD、配置文件，且目标功能在本仓库常有多个副本时。

## 六步法（BLOCKER，违反即事故）

1. **先确认用户看的是哪一份**：动手前先问/先查用户短链指向哪个文件，**不要默认"当前文件"**。同一功能多副本并存时，默认当前文件几乎必错（正式文件 / `*.bak-before-restore` 备份 / `_ng_cap_tmp/` 截图快照 / gh-pages 线上都可能各一份）。
2. **精准打点，禁整段替换**：先 grep 定位唯一锚点（如 `<span class="op">生成邀请码</span>` 在第 N 行），只删这一个元素 + 其紧邻分隔符；**禁止连带删所在行 / 相邻 tab / 样例数据行**（连带删除会让页面变空）。
3. **删完必须回用户短链验证**：拉线上内容（如 `gh api .../contents/<file>?ref=gh-pages -q .content | base64 -d`）→ grep 确认零命中，才算真删掉。本地删 ≠ 线上删 ≠ 用户看到的删。
4. **同一元素裁定要留痕**：若某元素曾被裁定"留/删"，必须写进项目 MEMORY.md 的「元素最终裁定清单」，不能只写当日日志——否则下一轮从零判断会推翻前次结论（典型：上午删→下午留→隔天又冒出来）。
5. **多文件归并/还原时做回归**：从备份/旧文件合并内容回正式文件后，**必须重跑一遍历史删除清单**（grep 全部已删元素应为 0 命中）——备份是删除前的状态，天然带毒。
6. **批量编辑必须串行 + 逐项回读验证，禁止相信「编辑成功」**（2026-09-15 事故）：
   - **串行**：同一文件的多次编辑**必须一条条串行发起**。并行发起时，后写会以同一份旧快照为准覆盖先写，**改动静默丢失、工具却仍返回成功**（实测一次 16 项改动里静默丢了 6 项，且当场 grep 才暴露）。
   - **逐项回读**：全部改完必须**逐项 grep 回读每个改动标记**（取新增文本里的独有片段做 key，`MISS` 即补做）。不要靠"我记得改过了"。
   - **旧行原样带回**：用「旧行 + 相邻锚点」作 `old_string` 时，`new_string` 必须把旧行原样带回，否则整行蒸发（实测把 V3.3 修订记录行吃掉，且不影响其他校验）。
   - **结构收尾校验**：最后跑一次标签/结构平衡校验（如 HTML 的 `<table>/<tr>/<td>/<ul>/<li>` 开闭配对），与**改动前基线**逐项对比——只看绝对值会漏判，必须相对基线看增量。
