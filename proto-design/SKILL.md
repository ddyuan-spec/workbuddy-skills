# 设计原型-C端平铺（proto-design）

C 端**平铺设计稿** skill（无交互、可复制源码、供墨刀/评审）。泰小虎项目强制先查知识库页面图再画。

## 触发（用户说这些即加载本 skill）
平铺 / 平铺图 / 设计原型 / 墨刀 / 可复制墨刀 / 可复制源码 / 平铺交互 / 原型平铺 / 评审板 / 跳转流平铺 / 无交互稿

## 范围
生成/修改任何 C 端**平铺设计稿**（无交互、可复制源码、供墨刀/评审板/跳转流铺排）时强制加载。产出是静态展示，不绑定点击事件。

## 原型修改总纲（PROTO-MOD-001，所有增量修改通用，BLOCKER）

> 上位原则：无论有无参考截图都生效，覆盖 `PROTO-REPLICA-001`（有参考图）/ `PROTO-FEAT-001`（禁臆测）。接到"改原型"先默念这一条。

接到「改原型 / 加个 XX / 优化一下」类需求时，遵循「复制为主、只增不改」：

1. **以复制为基底**：默认在**现有原型文件**上做最小改动，不重写、不重画、不换实现方式。要新建独立平铺稿演示新功能时，也从现有原型**复制出基底**，而非凭记忆新起一份。
2. **只动变更单内的点**：需求明确指出的「新增字段 / 新增入口 / 新增功能 / 明确要删或改的点」才动；先产出一份「变更清单」逐项核对，没列进去的都不碰。
3. **未列入清单一律保留**：现有字段、选项、文案、结构、样式、配色、间距——只要没在变更清单里，原样保留，**像素级不动**。
4. **禁止顺手动刀**：严禁借改原型之名顺手做「优化 / 清理 / 重做 / 统一风格 / 顺手改文案 / 换组件 / 调间距」等一切变更单之外的动作。这些动作即便「看起来更好」，也属违规改其他东西。
5. **改完必做 diff 自检**：对比改动前后，确认「只有变更单内的点变了，其余与改动前完全一致」；交付前在回复里给出改动范围小结。
6. **有异议先问**：拿不准某处「算不算该加的」，`AskUserQuestion` 反问，不要自己判断后顺手改。

违反本原则（乱改其他东西、顺手优化、凭记忆重画丢字段）= 禁止交付。

## 与「原型C端-交互」的边界（勿混）
| 产出 | 走哪个 skill | 关键差异 |
|---|---|---|
| 无交互、可复制源码、供墨刀/评审的平铺图 | **本 skill（proto-design）** | 走 FLAT 模块 + flat_delivery_checklist、顶部标「无交互」、不跑冒烟 |
| 带交互、可点击、有跳转/状态/弹窗 | **proto-c（原型C端-交互）** | 跑冒烟、三态拆独立页、JS 交互 |

## 强制门禁（自管）
0. **PROTO-INT-001 需求九步确认**（BLOCKER）：拿到需求先逐条对照九步清单（视觉标准/流程图/页面清单/状态规则/交互规则/特殊任务/示例数据/禁止项/验收标准），任一缺失必须 `AskUserQuestion` 让用户补全，齐全后才进后续门禁——禁止用户只给一句「做个XX原型」就直接开画/平铺。
1. **REQ-FLOW-022 知识库 UI 索引先行**（BLOCKER，项目级 taixiaohu）：画前先 Read `泰小虎UI_catalog.md` → `route_pages.py` 路由命中参考页；未命中反问「要参考哪页」。无 catalog 跳过。
2. **PROTO-STY-002/003**：首步定位设计规范 + 真实截图 1:1 套用（色值/描边/Tab 高亮）。
3. **PROTO-FLAT-001 先定 mode**：动手前必须用 AskUserQuestion 确认产出哪种平铺（review-board 带详情 Modal / flat-flow 纯截图无框 / modao 墨刀可复制源码），不得混用两套卡片规范。
4. **PROTO-FLAT-004 静态标注**：顶部明确标注「无交互 / 静态展示」，元素不绑点击。
5. **flat_delivery_checklist**（8 项，必须用工具验证不能凭记忆）：标题/截图核对、弹窗遗漏、截图时效性、红线、比例、占位、路径、质量。
6. **PROTO-REPLICA-001 参考图优先复刻工作流（BLOCKER，有参考图时强制）**：用户给了真机/参考截图时，禁止"边看截图边直接平铺最终版"。必须串行执行五步：①**盘点截图建基线**——逐屏读全参考图，列出每张图「原有字段清单 + 功能入口清单」（按钮/跳转/弹窗/表单），作为复刻基线；②**先复刻只搬运**——第一版严格 1:1 复刻截图现有字段与功能，不增不减不改结构；③**再读需求定位差异**——读需求/口述变更，产出「变更清单」（新增字段 / 删除字段 / 修改字段 / 改功能 / 新增功能，逐项列出）；④**按变更清单改**——只动清单内条目逐项改，未列入的现有字段/功能一律保留，禁止顺手"优化/清理/重做"；⑤**改完复查·臆造字段扫描（交付前强制）**——逐字段追问来源，只允许两类字段存在：**A 类=截图原有字段**（在基线里）、**B 类=需求要求字段**（在变更清单里）。既不在基线也不在变更清单的字段 = **臆造字段**，必须删除或 `AskUserQuestion` 反问确认后才留。交付前必须输出/核对一份「字段溯源表」（截图原有 / 需求新增），二者之外的即删。平铺稿顶部仍须标「无交互」（PROTO-FLAT-004）。这是 PROTO-FEAT-001「禁臆测」在"有参考图"场景的落地，同源见 proto-c / proto-admin。

## 标准流程
1. **知识库先行**：Read catalog → `route_pages.py "<关键词>"` → 只 Read 命中页；未命中反问。
   > 定位：`泰小虎UI_catalog.md` 与 `route_pages.py` 在**项目工作区根目录**（如 `C:/Users/13364/WorkBuddy/任务目标流程化/`），不在本 skill 目录。找不到时先 Glob `**/泰小虎UI_catalog.md` 定位；确实没有则跳过本分支。
2. **读基线**：PROJECT 设计规范 + 真实截图（1:1 套用）。**有参考截图时先按 PROTO-REPLICA-001 走五步（盘点建基线 → 1:1 复刻 → 再读需求出变更清单 → 只按清单改 → 复查臆造字段），严禁边看截图边直接出最终版。**
3. **定 mode**：review-board / flat-flow / modao（未明说则反问）。
4. **产平铺**：
   - flat-flow → 用 `references/flat-flow-template.html` 铺排，C端列宽 280px。
   - modao → 用 `scripts/gen_flat_modao.py`（整原型平铺）或 `scripts/gen_flat_popup.py`（单弹窗多变体）；只取 `<style>` 不带 `<script>`（真·无交互），JS 动态内容在 PATCHES/VARIANTS 静态补值；顶部「一键复制源码」复制 `<style>`+`.pf-board` outerHTML。
   - **states 抓取式平铺（JS 渲染重的交互原型首选，2026-09-16 新增）** → 用 `scripts/gen_flat_states.js`：先把交互原型的每个状态用 playwright **真实渲染再抓 DOM**，JS 动态内容（商品列表 / 订单卡片 / 金额计算 / 弹窗回填值 / 空态）自动就是真值，**无需手写 PATCHES 补值**（补齐 gen_flat_modao.py 的短板）。命令：`NODE_PATH="<含 playwright 的 node_modules>" <node> scripts/gen_flat_states.js --src <原型.html> --out <平铺.html> --states <states.json>`；states.json 为状态数组，每项 `{label, setup(抓取前执行的 JS), extras(要一并截入帧的兄弟元素 id，如弹窗), toast(强制显示的提示文案)}`。产出真·无交互（不含 script + 剥离 onclick/oninput）+ 顶部标「无交互」。
   - review-board → 卡片三件套（截图+页面名+查看详情按钮弹 Modal），顶部标「无交互」。
5. **跑 flat_delivery_checklist** 8 项 + 红线扫描（PROTO-TXT-007 Loop）。
6. **交付**：过 delivery-suite 推送 / 转 Word。

## 红线速记（详见 rules.json）
- 平铺六条红线（flat-flow）：禁缩略图网格/容器框/步骤序号/查看详情按钮/手机壳/冗长文字（PROTO-FLAT-002）
- 禁冗余说明文字 / tiny 限制标签 / NEW 角标（PROTO-TXT 系列）
- 截图三步防污染：隐藏侧栏 → 重置弹窗 → 白底（PROTO-FLAT-005）
- **平铺时手机框内页面高度必须用 `min-height:<设计高>`（如 812），不能只写 `height:auto`**：原型底部操作条多为 `position:absolute;bottom:0`，交互版靠固定视口承载；改成 auto 后短内容页的底部条会压住内容（实测：收银台「找朋友支付」行、确认订单「订单备注」块被盖住）。min-height 让短页保持设计高、长页自然增长，无需逐页补 padding（gen_flat_states.js 已内置）
- 有参考图时遵循「参考图优先复刻工作流」：先盘点截图建基线 → 1:1 复刻 → 再读需求出变更清单 → 只按清单改 → 改完复查，只保留「截图原有字段 + 需求要求字段」两类，其余臆造字段即删（PROTO-REPLICA-001，BLOCKER）
- 改原型（无论有无参考图）以复制为主、只增不改：以现有原型为基底做最小改动，只动变更清单内的点，未列入清单的现有字段/选项/文案/结构/样式一律保留，禁止顺手优化/清理/重做/改文案（PROTO-MOD-001，BLOCKER）
