# HTML 可视化就地编辑器

单文件 HTML 原型 / PRD 网页 / 简单页面的"所见即所得"文字编辑器。零 npm 依赖，只用 Node 内置 `http`。

## 何时用
- 用户拿到一份 HTML，想**直接改文字**，又不想碰代码、怕改乱版式；
- 用户要"人机双写"：人改文案、AI 改结构/数据/批量，二者读写同一份文件；
- 评审时临时改价格、文案、提示语看效果。

## 启动方式（关键）
脚本在 skill 目录 `scripts/`：`server.js` + `editor.html`（零依赖，仅 Node 内置模块）。

用**托管 Node**启动（路径以当前环境二进制为准，版本号见 binary_context）：
```
C:/Users/13364/.workbuddy/binaries/node/versions/22.22.2-2/node.exe <skill_dir>/scripts/server.js
```
- 监听 `127.0.0.1:8777`；启动后用 `present_files` 打开 `http://localhost:8777` 给用户。
- 用完跟用户确认后停服务：`netstat -ano | grep ":8777"` 找 PID，`taskkill /F /PID <pid>`。
- ⚠️ 关梯子/代理不影响本地 127.0.0.1；但若 WorkBuddy 读 env 代理变量导致 fetch 异常，清 `HTTP(S)_PROXY` 即可。

## 功能与人间双写纪律
- **打开**：粘贴本地 HTML 绝对路径点「打开」，或把 `.html` 拖进框（拖入需补全保存路径）。
- **编辑模式**：开启后点页面任意文字即就地改（进入即**自动全选**，打字即整体替换）；只改文字，不碰结构/样式。
- **保存写回**：改完点「保存写回」→ 写回**原文件同一路径**。
- **从磁盘刷新**：AI 改了同一文件后，用户点此即看到改动 → **人机双写不打架的关键**。
- **生成物⚠️提醒**：检测到平铺图/生成物（含「平铺图（无交互）」「无交互 / 静态展示」「GENERATED」等标记）自动弹警告，防用户在快照上白改。
- **让 AI 改**：「复制路径」发给我（WorkBuddy），结构/批量我来做，用户刷新即同步。

## 安全护栏（server.js 已实现并实测）
`/save` 拒绝写入 `Windows` / `System` / `Program Files` / `Users\*\AppData` 等保护目录（实测 AppData 被 403 拦下，workspace 内正常可写）。保存时强制 `DOCTYPE` 仅写一次、剥离 `contenteditable` 残留，不产生重复文档头。

## 使用边界（务必讲给用户）
- 最适合**文字直接写在标签里**的 HTML——平铺图、PRD HTML、简单页面，点哪改哪。
- **交互原型**很多文字是 JS 动态生成（`GOODS`/`ORDERS` 等数组 + `renderXxx()`），点不到、改不动 → 这类结构/数据改动必须走 AI（直接 Edit 源文件），不要指望编辑器点改。
- 双写分工：**人改文案 → 编辑器；AI 改结构/数据/批量 → 工具**。改完源文件后重生成平铺，用 `proto-design` 的 `gen_flat_states.js`（配 `*-flat-states.json`）。

## 实测结论（Playwright 真跑验证）
- 编辑链：打开→编辑模式→点字→全选→输入→保存→回读，全过；
- 文字**整体替换**非插入、`DOCTYPE` 计数=1 无重复、保存后**无 contenteditable 残留**、生成物警告触发、页面 0 JS 报错；
- 测试后源文件**字节级还原**，不污染交付物。

## 同源文本文件的可替代路径
若只是纯文案微调且用户不在意可视化，AI 也可直接 `Read`+`Edit` 同一 HTML（纯文本），与编辑器完全同源、刷新即同步——编辑器是为"非技术也想点哪改哪"的场景兜底。
