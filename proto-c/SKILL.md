# 原型C端-交互（proto-c）

C 端**带交互**前端原型 skill。泰小虎项目强制先查知识库页面图再画。

## 触发（用户说这些即加载本 skill）
画原型 / 改原型 / 前端原型 / C端原型 / App原型 / 小程序原型 / H5原型 / 手机端原型 / 带交互原型 / 可点击原型 / 高保真原型

## 范围
生成/修改任何 C 端**可交互**前端原型（App / 小程序 / H5 / 手机网页，含点击跳转、状态切换、弹窗、Toast、表单）时强制加载。

## 原型修改总纲（PROTO-MOD-001，所有增量修改通用，BLOCKER）

> 上位原则：无论有无参考截图都生效，覆盖 `PROTO-REPLICA-001`（有参考图）/ `PROTO-FEAT-001`（禁臆测）两条下位规则。接到"改原型"先默念这一条。

接到「改原型 / 加个 XX / 优化一下」类需求时，遵循「复制为主、只增不改」：

1. **以复制为基底**：默认在**现有原型文件**上做最小改动，不重写、不重画、不换实现方式。要新建独立原型演示新功能时，也从现有原型**复制出基底**，而非凭记忆新起一份（凭记忆重画极容易丢字段/丢入口）。
2. **只动变更单内的点**：需求明确指出的「新增字段 / 新增入口 / 新增功能 / 明确要删或改的点」才动；先产出一份「变更清单」逐项核对，没列进去的都不碰。
3. **未列入清单一律保留**：现有字段、选项、文案、结构、样式、配色、间距——只要没在变更清单里，原样保留，**像素级不动**。
4. **禁止顺手动刀**：严禁借改原型之名顺手做「优化 / 清理 / 重做 / 统一风格 / 顺手改文案 / 换组件 / 调间距 / 去边框」等一切变更单之外的动作。这些动作即便「看起来更好」，也属违规改其他东西。
5. **改完必做 diff 自检**：肉眼或工具对比改动前后，确认「只有变更单内的点变了，其余与改动前完全一致」；交付前在回复里给出改动范围小结（改了哪几项、保留了多少原有内容）。
6. **有异议先问**：拿不准某处「算不算该加的」，`AskUserQuestion` 反问，不要自己判断后顺手改。

违反本原则（乱改其他东西、顺手优化、凭记忆重画丢字段）= 禁止交付。

## 与「设计原型(平铺)」的边界（勿混）
| 产出 | 走哪个 skill | 关键差异 |
|---|---|---|
| 带交互、可点击、有跳转/状态/弹窗 | **本 skill（proto-c）** | 跑冒烟、三态拆独立页、JS 交互 |
| 无交互、可复制源码、供墨刀/评审的平铺图 | **proto-design（设计原型）** | 不跑冒烟、走 flat_delivery_checklist、标注「无交互」 |

用户只要平铺图/墨刀稿/可复制源码 → 直接路由到 proto-design，不要在本 skill 画完再「假装平铺」。

3. **PROTO-STY-003 真实截图 1:1 套用**：用户给了真机截图，逐字套用色值/描边/Tab 高亮，禁通用风格化。
4. **PROTO-STR-003 三态列表拆独立页**：状态≥3 必须拆独立移动端页，禁单页 Tab 切。
5. **PROTO-SMK 交互冒烟**：交付前必跑 `references/proto_smoke_client.js`，退出码 0 才许交付。脚本已含 **[A]–[J] 十段扫描**（页面归属 / go 可达 / 点击零错 / onclick 已定义 / JS 错误 / 表单去重 / [G] 逻辑反模式 / [H] 引用完整性·dead-reference / [I] 弹窗·浮层悬空扫描 / [J] 内嵌 `<script>` JS 语法校验），[H] 为防「脚本过期漏检」与「删定义留调用/样式」的机器门禁（见门禁 #8）；[I] 为防「getElementById 目标 id 不存在」导致点击弹窗/跳转空白或无反应（见门禁 #9，绿韵家图生图 V0.5 实测踩中：go('pageRecharge') 页面未定义、删 modalRefundConfirm 留调用）；[J] 为防「原型内嵌 `<script>` 自身有语法错误 → 整段脚本解析失败、全站交互死掉」（见门禁 #10，绿韵家 AI 创作原型实测踩中：`.tag.active')'].map(...)` 多余引号导致整站 JS 失效，但 HTML/CSS 正常、肉眼极难发现，[B]/[H1]/[I] 都查不出「脚本能否解析」）。
6. **PROTO-SMK-005 交互逻辑审计**（BLOCKER）：冒烟通过 ≠ 可交付。交付前必须跑冒烟脚本的 **[G] 交互逻辑反模式扫描**（自动卡住「累加函数定义了却从不调用 / 完成或跳转用 Math.random 决定 / 完成处理器只翻显示不碰真实任务数据」三类硬伤），并**人工逐项核对 checklist 的 C24（状态机一致性）/ C25（数值累加真实生效）/ C26（无随机跳转与垃圾数据）**，任一项不通过禁止交付。
7. **PROTO-SMK-006 真实点击穿透（BLOCKER，最后一道关，通用、不限项目）**：交付前必须跑项目专属点击穿透脚本 `references/<项目>-clickthrough.js`（与原型放**同目录**，头部 `@proto "原型.html"` 声明归属），用 jsdom 模拟真人**逐个点击每个交互入口并断言状态真的变了**（数值有无 +N、页面有无切换、弹窗有无出现、入口卡片/顶部 Tab 有无死交互）。退出码非 0（出现死交互或状态不联动）**禁止交付**。这是冒烟（只查「点一下不报错」）和 [G] 扫描（只查「写法反模式」）都查不出的「交互结果正确性」兜底——**绝不允许只跑了冒烟/[G] 就宣布交付**。新项目/新原型无专属脚本时，先 `cp references/clickthrough-template.js <项目>-clickthrough.js` 并按真实路径补 Step。**新增任何交互入口（新页面/新按钮/新 Tab）必须同步在脚本补对应 Step 的点击+断言**，否则 [H1] 会报「该页面未被点击穿透脚本覆盖」强制你补 Step。skill 自带的 `references/proto_clickthrough_client.js` 仅作泰小虎示例/模板，不再作为其他项目的默认脚本。
8. **PROTO-SMK-007 引用完整性 / dead-reference 扫描（BLOCKER，嵌入冒烟 [H] 段）**：覆盖本次（睡眠任务闭环 v7）迭代实测踩中的三类回归——**R1** 点击穿透脚本断言的是历史旧 id，与原型对不上 → 测试假通过、漏检真交互；**R2** 删了函数定义却残留调用（如 `renderHuli()`）→ 运行期 ReferenceError，主流程弹窗弹不出；**R3** 删了 CSS 类定义却残留 `class` 引用（如 `.huli-btn`）→ 按钮样式崩。机器门禁：**[H1]** 点击穿透脚本（`*-clickthrough.js`，与冒烟同目录、按 `@proto` 声明自动发现并归属到当前原型；skill 自带 `proto_clickthrough_client.js` 仅作泰小虎示例）引用的每个 `#id` 必须在原型中存在（否则该 Step 会 null 崩溃，正是 R1），并反向报出未被脚本覆盖的 `.page`（强制补 Step）；**[H2]** 原型 `<script>` 调用的每个裸函数必须已定义（否则 ReferenceError，R2）；**[H3]** 原型使用的组件类必须在 `<style>` 有规则（WARN，R3）。**[H1][H2] 不通过禁止交付**；扫描前已剥离 `//` 与 `/* */` 注释，避免注释文本误判。
9. **PROTO-SMK-008 弹窗·浮层悬空扫描（BLOCKER，嵌入冒烟 [I] 段）**：覆盖绿韵家图生图 V0.5 实测踩中的「点了跳转/弹窗却空白或没反应」——根因是 `go('pageRecharge')` 指向一个从未定义的页面，或删了弹窗定义（如 `modalRefundConfirm`）却残留 `getElementById('...').classList.add('active')` 调用。门禁：**原型 `<script>` 中每个 `getElementById('id')` 的 `id` 必须在 DOM 中存在**，否则报「悬空引用」并禁止交付。注意 `[B]` 只校验 `go()` 页面目标、不查弹窗，本段专门补这个盲区。凡修改/新增任何跳转或弹窗入口，必须重跑冒烟让 [I] 复核。

10. **PROTO-SMK-009 内嵌 `<script>` JS 语法校验（BLOCKER，嵌入冒烟 [J] 段）**：覆盖绿韵家 AI 创作原型实测踩中的「整站 JS 死掉」——原型内嵌脚本有一处 `.tag.active')'].map(...)` 多余引号，导致整段 `<script>` 解析失败、所有交互（页面切换/生成/弹窗）全部失效，但 HTML/CSS 渲染正常、肉眼极难发现。门禁：**把原型每段内嵌 `<script>` 抽出来跑 `node --check`（与运行 jsdom 同一 node 二进制、口径一致），一旦 SyntaxError 直接判 BLOCKER 禁止交付**。注意 `[B]/[H1]/[I]` 只校验「元素 id 是否存在 / 函数是否定义 / getElementById 目标是否存在」，全都查不出「脚本本身能否解析」——这是唯一能抓「整站 JS 死掉」的机器门禁。凡手写/AI 生成/复制粘贴原型 JS，交付前必须重跑冒烟让 [J] 复核（重点盯：多余引号、未闭合括号、模板字符串 `${}` 错位、中文引号混入）。
11. **PROTO-SMK-011 复制源码标准组件（REQUIRED，墨刀交付件）**：所有交付原型必须带「复制源码」能力，且严格按 `references/copy_source_component.html` 标准组件实现，**禁止自由发挥**。① **放置位置**：`.copy-bar` 必须是 `<body>` 内、`.phone` 之外的**第一个子元素**（`position:sticky;top:0`），**严禁**塞进手机框内部做悬浮按钮（会遮挡内容、破坏视觉——绿韵家新人礼包原型实测踩中）；② **双按钮**：工具条同时提供「复制当前页」（所见即所得，抓取当前 `.page.active`/`.view.active` 包成独立可运行 HTML，供用户**挑页复制**：只把要用的页面粘到墨刀）与「复制全部源码」（初始纯净态整份文件，从首屏即可运行）；③ **复制实现**：`navigator.clipboard` 优先 + `execCommand` 兜底，函数名以 `__proto` 前缀避免与原型业务函数（如 `doCopy`/`showToast`）撞名（撞名会静默覆盖、引发点击穿透失败）；④ **独立可运行**：复制当前页必须包 `<div class="phone">` 外壳 + 完整 `<style>`，保证粘到墨刀单屏直接可运行。交付前目视确认：工具条在顶部、不遮挡内容、两个按钮均可点击不报错。

12. **SPEC-000 原型 spec 前置门禁（BLOCKER，生成前强制路由到 proto-spec）**：凡要画 / 改 C 端交互原型，**先加载 `proto-spec` 跑前置拆解**——新建多页必出三件套（NAV-MAP / PUBLIC-SPEC / PAGE-SPEC）并经用户确认；增量改必跑 SPEC-004 影响判定（单页 / 全局）。未跑 proto-spec 直接开画视为违反本门禁。proto-spec 的 SPEC-003 导航地图登记门禁在此同步生效：任何 `go('xxx')` 跳转必须先登记到 NAV-MAP，冒烟 [B] 段会反向校验「原型里出现的跳转目标都已在 NAV-MAP 登记」。
13. **SPEC-004 增量修改影响范围门禁（BLOCKER）**：接到「改原型」需求先判定影响域——只改某页内部=单页（仅重跑该页八项 + 该页点击穿透）；动 PUBLIC-SPEC token / style.css / 公共组件 / 影响其他页跳转=**全局**（必须重跑全量八项验收 + 全量点击穿透）。判定错了导致漏验，禁止交付。
14. **PROTO-REPLICA-001 参考图优先复刻工作流（BLOCKER，有参考图时强制）**：用户给了真机/参考截图时，禁止"边看截图边直接画最终版"。必须串行执行五步：①**盘点截图建基线**——逐屏读全参考图，列出每张图「原有字段清单 + 功能入口清单」（按钮/跳转/弹窗/表单），作为复刻基线；②**先复刻只搬运**——第一版严格 1:1 复刻截图现有字段与功能，不增不减不改结构；③**再读需求定位差异**——读需求/口述变更，产出「变更清单」（新增字段 / 删除字段 / 修改字段 / 改功能 / 新增功能，逐项列出）；④**按变更清单改**——只动清单内条目逐项改，未列入的现有字段/功能一律保留，禁止顺手"优化/清理/重做"；⑤**改完复查·臆造字段扫描（交付前强制）**——逐字段追问来源，只允许两类字段存在：**A 类=截图原有字段**（在基线里）、**B 类=需求要求字段**（在变更清单里）。既不在基线也不在变更清单的字段 = **臆造字段**，必须删除或 `AskUserQuestion` 反问确认后才留。交付前必须输出/核对一份「字段溯源表」（截图原有 / 需求新增），二者之外的即删。这是 PROTO-FEAT-001「禁臆测」在"有参考图"场景的落地，也是 2026-09-03「严格复刻只加功能」血泪教训的流程化（后台同源见 proto-admin）。

5. **交互逻辑审计 + 人工 checklist**（**务必真正逐项执行并报告每项证据，禁止只跑冒烟就宣布交付**）：
   - 先跑冒烟脚本的 **[G] 交互逻辑反模式扫描**，G1（累加函数定义了却从不调用）/ G2（完成或跳转用 Math.random 决定）必须为 0 失败；G3（完成处理器只翻显示不碰真实任务数据）警告必须人工核对确认非假完成。
   - 再逐项核对 rules.json `checklist` 全部条目（当前 **C01–C28**），重点执行 **C24 状态机一致性 / C25 数值累加真实生效 / C26 无随机跳转与垃圾数据 / C27 真实点击穿透 / C28 主流程贯穿** 五项交互逻辑审计——含状态机的原型必须实际走一遍主流程断言结果（领→列表填充、完成→数值 +N、页面状态联动），而非只验证「点一下不报错」。
   - 最后跑红线扫描（PROTO-TXT-007 Loop）。
   任一项不通过禁止交付（PROTO-SMK-003：冒烟通过 ≠ 可交付；PROTO-SMK-005/006：交互结果正确性强制门禁）。
6. **真实点击穿透（PROTO-SMK-006，强制，通用）**：跑项目专属点击穿透脚本 `<项目>-clickthrough.js`（与原型同目录，已带 `@proto` 声明）：
   `NODE_PATH="<node_modules>" <node> <项目>-clickthrough.js <原型.html>`，退出码非 0 禁止交付。
   新项目无脚本时先 `cp references/clickthrough-template.js <项目>-clickthrough.js` 并按真实路径补 Step。**本测试脚本必须随原型迭代同步更新**（新增交互入口要在脚本补 Step），否则该入口视为未验证；冒烟 [H1] 也会自动发现该脚本并校验其 #id 不悬空。
7. **交付**：过 delivery-suite 推送 GitHub Pages / 转 Word；PRD 引用其截图时过 prd-suite。

## 红线速记（详见 rules.json）
- 禁冗余说明文字 / tiny 限制标签 / 选项态 hint 小字 / NEW 角标（PROTO-TXT 系列）
- 禁新建气泡/弹窗样式组件，复用全局 Toast（PROTO-STY-006）
- 提示只在实际提交动作触发，不在切换选项时（PROTO-STR-005）
- 复用既有同模块原型，禁静默删字段（PROTO-STR-006/007）
- 需求九步未确认齐全不动手，缺的先问用户补（PROTO-INT-001）
- 复制源码必须是顶部 `.copy-bar` 标准组件（双按钮：复制当前页 + 复制全部源码），严禁手机框内悬浮复制按钮（PROTO-SMK-011）
- 多页新建必须先跑 proto-spec 出三件套并确认设计规范；增量改先判单页/全局（SPEC-000 / SPEC-004）
- 设计规范（色板/token/视觉签名）必须用户逐项确认，禁"自动命中基线就默认采用"的兜底（SPEC-002）
- 任何 `go()` 跳转必须先登记到 NAV-MAP，禁未登记跳转（SPEC-003）
- 禁止臆测/过度实现功能：严格按需求做，不擅自加需求未涵盖的 CRUD/交互（编辑/状态切换/批量/新增等），多出来的即删；需求不明先反问（PROTO-FEAT-001，BLOCKER）
- 有参考图时遵循「参考图优先复刻工作流」：先盘点截图建基线 → 1:1 复刻 → 再读需求出变更清单 → 只按清单改 → 改完复查，只保留「截图原有字段 + 需求要求字段」两类，其余臆造字段即删（PROTO-REPLICA-001，BLOCKER）
- 改原型（无论有无参考图）以复制为主、只增不改：以现有原型为基底做最小改动，只动变更清单内的点，未列入清单的现有字段/选项/文案/结构/样式一律保留，禁止顺手优化/清理/重做/改文案（PROTO-MOD-001，BLOCKER）
- 所有「删除」操作必须二次确认：点击删除先弹确认（展示对象名 + 不可恢复提示），确认才执行，禁止点击即删；统一用可复用的 confirmAction 类组件，各删除入口不得各写一套（PROTO-DEL-001，BLOCKER）
- 全局函数名禁与宿主/DOM 元素属性同名（scrollTop / scrollLeft / scrollTo / click / focus / blur / open / close / remove / title / name / content / text / value 等）——内联 onclick 的作用域链里元素自身属性会遮蔽同名全局函数，点击静默失效且不崩整站；一律带业务前缀（backTop() / openBuyModal() / closeBuyModal()）（PROTO-NAM-001，2026-09-14 绿韵家水卡原型实测踩中）
- 横向 tab/筛选栏所有项必须在视口内完整可见：禁固定大 padding 导致末项挤出可视区、禁用 overflow-x:auto 掩盖溢出（用户不会主动横滑=功能丢失）；选中态配色/指示器（宽/高/距底）须从基线截图「像素采样」确定，禁凭品牌主色臆断（PROTO-TAB-001，2026-09-15 绿韵家水卡原型实测踩中：「已完成」被挤出 + 选中态想当然用 C 端绿而非基线黑字+绿下划线）
- 原型视觉验收截图用真实浏览器引擎（playwright chromium）截，勿用 Edge headless——后者时机不可靠会漏掉「样式崩」类视觉问题（v7 复盘 R5）

## 关联
- `requirement-workflow`：lite 入口收口壳，信息不全时路由进来做 intake；门禁已自管。
- `proto-spec`：**生成前强制前置**——出三件套（NAV-MAP/PUBLIC-SPEC/PAGE-SPEC）+ 三道门禁（设计规范确认 / 导航地图登记 / 增量影响判定）+ 八项验收基线，先文字确认再画 HTML。
- `proto-design`：**平铺图/墨刀/可复制源码**走它，勿混。
- `proto-admin`：后台原型独立 skill，两端要求不同。
- `prd-suite` / `delivery-suite`：原型定稿后过结构排查与推送。
